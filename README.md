# Проект «SkillSwap»

### Проект «SkillSwap» — платформа обмена навыками «Я научу / Хочу научиться»

SkillSwap — одностраничное (SPA) приложение, в котором пользователи публикуют
навыки двух типов:

“Учу” — навыки, которыми пользователь готов делиться;

“Учусь” — навыки, которым пользователь хочет научиться.
Сервис позволяет находить взаимно подходящие пары, отправлять заявки на обмен и
вести список текущих/завершённых сессий. Все данные берутся из JSON-моков на json - server;

## Запуск проекта

1. Клонируем репозиторий `git clone link-to-repo`
2. Устанавливаем зависимости: `npm install`
3. Настроить переменные окружения в .env файле: `VITE_SKILLSWAP_API_URL=http://localhost:PORT`
4. Запуск проекта `npm run dev` - запускает фронтенд
5. Можно запустить тесты с изображением покрытия приложения в отдельном терминале `npm run test:coverage`

## Основные возможности:

- Публикация навыков — создание пользователя с карточкой навыка(то чему хочет научить, взамен на какой либо навык)
- Фильтрация и поиск - поиск по фильтрам(город, пол и т.д), поиск в строке поиска по навыкам.
- Обмен навыками — отправка обмена навыка(фиктивная функция)
- Избранное — сохранение избранных в локальное хранилище каждого пользователя.
- Тёмная/светлая темы - настраивается в зависимости от системных настроек, а так же по выбору.

## SkillSwap API

SkillSwap API построена на основе класса-родителя Api, расположенной в src/shared/api/api.ts.

### Класс родитель Api (Shared)

Класс имеет поля `baseURL` и `uri` для составления адресного пути запросов в классах потомках. В качестве `baseURL` используется .env переменная с адресом json-сервера. Реализует методы проверки ответа `checkResponse` и `get` для получения данных через метод GET. Типизируются дженериками - что передалось в get по типу, то передастаться и в checkResponse.

Имеет Реэкспорт из index.ts (api, shared)

### Классы CategoriesApi, SubCategoriesApi, CitiesApi (Entities)

Классы наследуются от класса Api. Реализуют свои эндпоинты `uri` через конструктор родителя методом super, и только получают свои данные от сервера, используя уже протипизированный для каждого класса метод get. Типизация в файле types.ts папки api

Имеют Реэкспорт из index.ts (api, (cities/categories/subcategories))

### Класс UserApi (Entities)

Класс наследуется от класса Api. Реализует свои эндпоинты `uri` через конструктор родителя методом super. Имеется приватное поле количества раундов соли `saltRounds` для хеширования пароля.

Имеет Реэкспорт из index.ts (api, users)

Поля класса:  
`private readonly saltRounds: number` - количество раундов соли для хеширования пароля.

Асинхронные методы:
`private hashPassword(data: string): Promise<string>` - используется только внутри класса в методах где нужно захешировать новый пароль пользователя. Принимает обычный пароль, возвращает захешированный.

`private comparePasswords(plainPassword: string, hashedPassword: string): Promise<boolean>` - используется только внутри класса в методе логирования, где нужно сравнить введеный пароль и существующий пароль пользователя. Принимает обычный введеный пароль и пароль пользователя на сервере, возвращает промис True/False.

`validateData<T>(data: T, schema: yup.Schema<T>): Promise<T>` - Этот метод вызывается до передачи данных на сервер. Метод принимает данные (обьект) которые нужно провалидировать и схему валидации согласно типа передаваемых данных. Возвращает промис с данными переданного типа.
ВАЖНО! Прогоняет все поля (abortEarly:false) и обрезает лишние переданные поля которых нет в схеме валидации (stripUnknown: true).

`getUsers(): Promise<TUser[]>` - метод ничего не принимает и возвращает промис массива пользователей с сервера.
ВАЖНО! Возвращает массив пользователей без паролей (passwordHash).

`getUserById(id: string): Promise<TUser>` - метод принимает id пользователя, которого нужно получить и возвращает промис пользователя с сервера.
ВАЖНО! Возвращает пользователя без пароля (passwordHash).

`userLogin(data: TLoginUser): Promise<TUser>` - метод принимает данные для логирования (пароль и эл почта) и возвращает промис пользователя с сервера если такой юзер имеется по почте.
ВАЖНО! Возвращает пользователя без пароля (passwordHash).

Принцип работы:
Делается запрос на сервер на поиск пользователя по переданной эл почте. Получаем ответ и если полученный массив пользователей пустой то выкидываем ошибку что такого юзера нет.
Если юзер нашелся по почте, то выполняется сверка введенного пароля и пароля юзера найденного по почте на сервере. Если не равны кидаем ошибку. Далее успешно получаем залогиненного пользователя (без пароля)

`userRegister(data: TRegisterUser): Promise<TUser>` - метод принимает данные для регистрации (данные пользователя без id, но с паролем) и возвращает промис с новым пользователем с сервера если успешно.
ВАЖНО! Возвращает пользователя без пароля (passwordHash).

Принцип работы:
Делается `GET` запрос на сервер на поиск пользователя по переданной эл почте. Получаем ответ и если полученный массив пользователей не пустой то выкидываем ошибку что пользователь уже существует с данной почтой. Если пустой, то продолжаем регистрацию. Хешируем переданный пароль и передаем методом `POST` на сервер данные уже с хешпаролем.
Далее успешно получаем зарегистрированного пользователя (без пароля)

`userPassUpdate(id: string, data: Pick<TRegisterUser, 'password'>): Promise<TServerUser>` - метод принимает id пользователя текущей сессии и новый пароль и возвращает промис с серверным пользователем (с хешпаролем).
ВАЖНО! Поразумевается бизнес логика отдельного обновления пароля от обновления данных пользователя. Свой инпут и кнопка "Обновить пароль".

Принцип работы:
Пароль хешируется и обновляется методом PATCH на сервере. Возвращаем успешно обвноленного пользователя для просмотра (с хешпаролем)

`userDataUpdate(id: string, data: TUpdateUser): Promise<TUser>` - метод принимает id пользователя текущей сессии и обьект с данными которые нужно обновить и возвращает промис с пользователем (без хешпароля). Обновляет методом PATCH только те поля, которые передали, а не всего пользователя сразу.

Принцип работы:
Данные обновляются методом PATCH на сервере. Возвращаем успешно обвноленного пользователя для просмотра (без хешпароля)

`userRemove(id: string): Promise<TServerUser>` - метод для чистки сервера, удаляет юзера по ID.

### Класс OffersApi (Entities)

Класс наследуется от класса Api. Реализует свои эндпоинты `uri` через конструктор родителя методом super.

Имеет Реэкспорт из index.ts (api, offers)

Асинхронные методы:

`validateData<T>(data: T, schema: yup.Schema<T>): Promise<T>` - Этот метод вызывается до передачи данных на сервер. Метод принимает данные (обьект) которые нужно провалидировать и схему валидации согласно типа передаваемых данных. Возвращает промис с данными переданного типа.
ВАЖНО! Прогоняет все поля (abortEarly:false) и обрезает лишние переданные поля которых нет в схеме валидации (stripUnknown: true).

`getOffers(): Promise<TOffer[]>` - метод ничего не принимает и возвращает промис массива предложений с сервера.

`getOfferById(id: string): Promise<TOffer>` - метод принимает id предложения, которого нужно получить и возвращает промис предложения с сервера.

`createOffer(userId: string, data: TOfferCreate): Promise<TOffer>` - метод принимает данные для создания предложения и id пользователя, к которому относится данное предложение. Возвращает промис с новым предложением с сервера если успешно.

ВАЖНО! Создание нового предложения происходит только после успешной регистрации пользователя. В ответ после регистрации получаем данные нового пользователя, берем id и передаем на создание нового предложения.

Принцип работы:
Собираем данные в один обьект и передаем в Post запрос на создание нового предложения

`offerDataUpdate(data: TOfferUpdate): Promise<TOffer>` - метод принимает обьект с данными предложения которые нужно обновить и возвращает промис с обновленным предложением. Обновляет методом PATCH только те поля, которые передали, а не все предложение.

Принцип работы:
Данные обновляются методом PATCH на сервере. Возвращаем успешно обвноленное предложение для просмотра.

`offerRemove(id: string): Promise<TOffer>` - метод для чистки сервера, удаляет предложение по ID.
